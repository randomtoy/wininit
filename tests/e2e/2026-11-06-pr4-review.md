# PR 4 review and Windows Server 2025 guest validation

Date: 2026-11-06. Product code reviewed and tested: `8259ead`, following the
original PR candidate `fd5a23b`. This is a bounded guest validation record,
not completion of the full Windows/OpenStack compatibility matrix.

## Environment and scope

- Windows Server 2025 Standard Evaluation, AMD64, version 10.0.26100.32230.
- Non-domain-joined VM reporting `Standard PC (Q35 + ICH9, 2009)`.
- Elevated SSH administration; existing Windows OpenSSH Server.
- No previous wininit service, installation, ProgramData directory, or Registry
  state at the installation paths used by this test.
- Cross-compiled native Go test executables and checksum-verified CI MSI/EXEs;
  no Go installation was required in the guest.
- The administrator explicitly prohibited reboot. Tests kept both active and
  configured hostnames unchanged and verified that the boot time did not change.

Credentials, host addresses, private/public keys, account names, raw metadata,
and license information are intentionally absent from this record.

## Review corrections

1. **Existing empty SSH key files were confused with absent files.** With an
   empty desired key list, an existing zero-byte `authorized_keys` could retain
   an unsafe ACL. Revoking a user with no profile could also create an
   unnecessary profile or `.ssh` directory while reporting no change. The
   adapter now tracks file existence explicitly, repairs an existing empty
   file atomically, and skips creation of absent revocation targets.
2. **Trusted-parent validation omitted `FILE_DELETE_CHILD`.** A parent directory
   could pass validation despite granting ordinary users the right to delete
   its protected children. The dangerous-rights mask now includes that right.
3. Documentation now describes implemented external execution, the SSH access
   policy precondition, and the distinction between the aggregate instance ID
   and hashed per-plugin operation inputs.

Native regression tests were built against the original implementations via
a Go build overlay, then against the corrected code. The original versions
failed at the reviewed boundaries; the corrected native suite passed. The
empty-file ACL, absent file/profile/directory, rerun, and parent-delete-right
cases are retained in repository tests.

## Cleanup

The exact original raw SAM settings were restored and compared with their
snapshot. The owned account/profile and temporary group membership were
removed. MSI uninstall passed, including preservation of configuration and
Registry state. Those review-owned installation/state paths were then purged
only because initial inspection established that none existed before testing.
Windows retained the logged-out fixture's registry hives after SSH use;
cleanup unloaded only those owned hives after confirming that the fixture
owned no process. This did not restart sshd or alter another user's profile.
No plugin processes remained; sshd stayed running. Temporary guest review
files and local private fixture keys were removed after collecting evidence.

## Validation limits

This run used an explicit local ConfigDrive seed. It did not attach or discover
CIDATA/config-2 media, provision a real OpenStack instance, establish KVM
acceleration, test Windows Server 2022, or perform rename/reboot/resume. Those
acceptance cases remain pending. Hosted CI separately checks formatting, vet,
unit/race tests, Windows native tests, checksums, and MSI smoke behavior; the
[corrected-code PR run](https://github.com/randomtoy/wininit/actions/runs/42212788357)
passed before this documentation-only validation record was added.
